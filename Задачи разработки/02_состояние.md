## Как добавить проект

Создать файл `src/content/projects/имя-проекта.md`:

```markdown
---
title: "Название"
client: "Клиент"
year: 2026
categories: [vfx, character]  # character | vfx | motion2d | neuro
production: "shoot"           # shoot | cg — необязательно
cover: "/placeholder/frame-01.jpg"
order: 20260315                # дата ГГГГММДД, больше — новее и выше в сетке
draft: false                  # true — не показывать
---

Текст ниже — Markdown, это описание проекта и, если нужно, `## Credits`.
```

Про `videos` (ролики с плеем на странице проекта) — см. `04_страница_проекта.md`.

### Порядок и как его менять

`order` — дата в формате `ГГГГММДД` (например `20250315`), больше значит новее и
выше/левее в сетке (изменено 20 августа 2026 — раньше было произвольное число с
шагом 10, потом 100; сортировка в коде тоже развёрнута под это, см. `Home.astro` и
`projectPaths.ts`). Поправить можно в любой момент, просто поменяв цифры — это не
создаёт проблем с зазорами, дата по сути просто большое число.

**Когда точная дата внутри года неизвестна** (25 августа 2026) — не ставим везде
`01.01`: это создаёт кучу проектов на одном дне и нечем разрулить порядок внутри
года без пересчёта соседей. Вместо этого месяц (день всегда `00`) выбирается
делением пополам от центра года: первый проект в году — `0600` (середина),
следующий — середина большего из оставшихся пустых промежутков (при равных
промежутках берётся более ранний). Для 1–2 проектов в году: `0600`, `0300`. Так
всегда есть куда вписать реальную дату позже без пересчёта остальных. Порядок
внутри года можно и нужно поправлять руками под смысл (например, поставить более
удачный ролик раньше в году, чтобы он был виднее) — это уже сделано вручную для
нескольких проектов (Детская Сберкарта, ОСАГО, Hbox, Добрый Лось).

Имя файла становится адресом страницы: `unity.md` → `/project/unity`.
Если обязательное поле пропущено — сборка остановится и скажет какое.

## Хостинг сайта — история решения (30 августа 2026)

Изначально был Cloudflare Pages (см. таблицу выше — решение сменилось). Ход
рассуждения:

1. 25 августа: обнаружено, что `b-cdn.net` (Bunny CDN) не открывается без VPN
   у автора; внешняя проверка показала `200 OK`, то есть дело не в
   конфигурации зоны, а похоже на блокировку на уровне провайдера/страны.
2. Тест через check-host.net по прямой ссылке на картинку: 2 из 3 российских
   узлов — ок, 1 — таймаут. Не полная блокировка, но нестабильно.
3. Проверили сам домен `maxsobolev.com` — отвечает (ping/http ок), но это
   ничего не говорило о доступности самого Cloudflare Pages: при проверке
   заголовков ответа (`Server: cloudflare`) стало ясно, что сайт крутится
   именно на Cloudflare — то есть под тем же риском, что и Bunny CDN.
4. Разобрали альтернативы для сайта: Amvera, Yandex Cloud Object Storage +
   CDN, VK Cloud Object Storage, Selectel — все российские, деплой чуть
   сложнее (кроме Amvera — она ближе всего к опыту Cloudflare Pages: git push
   → автосборка → деплой).
5. Отдельно проверили риск в обратную сторону — доступность российской
   инфраструктуры НЕ из России. Подтверждённый прецедент: в 2023 году
   Латвия, Финляндия и Норвегия заблокировали Яндекс целиком на уровне
   государства. По Amvera/VK Cloud/Selectel конкретных данных нет ни за, ни
   против.
6. Решение: сейчас важнее российская аудитория → переезд на Amvera Cloud.
   Риск потери части зарубежной аудитории — принят сознательно, не забыт.

**Bunny CDN (картинки/видео)** — решение по нему не менялось, остаётся Bunny.
Тест показал 2/3, не полную блокировку; при дальнейших проблемах кандидат на
замену — Cloudflare Images/Stream или тот же путь, что для сайта.
