# 04 — Страница проекта

Записано: 19 августа 2026. Обновлено: 20 августа 2026 — после первых реальных
видео пересмотрена подача нескольких роликов (было: список блоков, стало: один
плеер + миниатюры-переключатели) и параметры кадрирования героя.

## Структура сверху вниз

1. **Герой** — один плеер (компонент `VideoHero`): кадр со скрабом (как на плитке главной) + кнопка плей поверх, если есть видео.
2. **Миниатюры роликов** — если у проекта их больше одного, ряд маленьких кнопок сразу под героем («Ролик 1» / «Ролик 2» / «Ролик 3»). Клик подменяет ролик в том же плеере и сразу запускает воспроизведение.
3. **Заголовок** — название, клиент / год / категории / съёмка-full CG.
4. **Мой вклад** — текст из тела файла проекта (Markdown). Тут же, если нужно, `## Credits`.
5. **Пред / след** — уже есть, не меняется.

Отдельной страницы на каждый ролик нет и не планируется — усложнение ради того же результата, который миниатюры дают в одном месте.

## Герой и видео: скраб → плей → переключение

Не автоплей на загрузке страницы. Последовательность:

1. По умолчанию — кадр (`poster` первого ролика, или `cover` проекта) со скрабом: курсор панорамирует по кадру, бежит таймкод. Тот же приём, что на плитках главной.
2. Поверх — кнопка ▶, если у видео есть `embed`-ссылка.
3. Клик по плею — кадр меняется на видео, начинается воспроизведение.
4. Если роликов больше одного — под героем миниатюры. Клик по миниатюре — герой сразу переключается на выбранный ролик и играет его (без промежуточного шага «сначала кадр, потом плей»).
5. Если `videos` не указано вовсе — кнопки плей нет, просто кадр со скрабом. Страницу можно свёрстывать и наполнять текстом до того, как появится видео.

`embed` понимает два вида ссылок: прямой файл (`.mp4`/`.webm`/`.mov`/`.m3u8`, локальный из `media-local/` или с CDN) — тогда это обычный `<video controls>`; любой другой адрес — считается ссылкой на встраиваемый плеер (Vimeo/Bunny) и идёт в `<iframe>`. Определяется по расширению в ссылке, руками ничего указывать не нужно.

## Кадрирование героя (правка от 20 августа)

На реальных фото и видео (не мелких стоковых заглушках прототипа) выявилось два момента:

- **Зум панорамы кадра** был рассчитан на маленькие превью в сетке (200%) — на полноэкранном герое с настоящим фото это выглядело избыточно. Для героя зум снижен до 130%.
- **Видео/iframe растягивались**, если пропорции ролика не совпадали с фиксированной высотой героя (60vh). Добавлен `object-fit: cover` — видео заполняет герой без искажений, обрезая то, что не влезает по высоте/ширине. Это осознанный выбор, не костыль: кадрирование по высоте — стандартный приём для полноэкранных видео-геро.

## Мой вклад / кредиты — это Markdown-тело файла

Отдельного поля для кредитов нет: у проектов слишком разная структура (где-то соло, где-то большая команда), под это не нужна жёсткая схема. Пишется прямо в файле проекта под frontmatter:

```markdown
---
title: "Черкизово"
...
---

Работал супервайзером по CG на два ролика для Черкизово...

## Credits
- Режиссёр — Имя Фамилия
- Продюсер — Имя Фамилия
```

Рендерится как обычный HTML: заголовки, абзацы, списки, картинки (`![подпись](/placeholder/frame-01.jpg)`). Когда появятся кадры «до/после» — вставляются просто как две картинки подряд в тексте, без отдельного компонента. Отдельный слайдер до/после — не сейчас, в открытых вопросах ниже.

## Несколько роликов на проекте (Черкизово, Wink, H-box…)

Один герой, под ним ряд миниатюр-кнопок — по одной на ролик. Подпись кнопки — `label` (короткая: «Кат 1», «30 сек»), если не задан — автоматически «Ролик 1», «Ролик 2»… Клик переключает и сразу играет. Каждый ролик — свой `embed` + свой `poster`, необязательный (если нет — берётся `cover` проекта).

## Изменения схемы (`content.config.ts`)

```ts
videos: z.array(z.object({
  label: bilingual.optional(),   // подпись ролика, если их несколько
  embed: z.string(),             // Vimeo/Bunny-ссылка ИЛИ прямой .mp4/.webm/.mov/.m3u8
  poster: z.string().optional(), // кадр-превью; если нет — cover проекта
})).optional(),
```

Если поле `videos` не указано вовсе — герой остаётся кадром без плея (текущее поведение всех 12 заглушек не ломается).

## Что не меняется

- Плитки на главной, скраб, фильтры — без изменений.
- Отдельного поля `role` в схеме нет: роль автора на всех проектах одна — CG/VFX Supervisor,
  она уже написана в шапке сайта под именем. Дублировать её на каждой странице проекта незачем.
